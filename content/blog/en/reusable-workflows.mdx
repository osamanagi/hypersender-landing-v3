A single notification can be straightforward. The challenge arrives when several parts of your application need to send similar messages.

## Name the event first

Start with the event that matters to the user, such as an order confirmation or a requested account update. Keep the event separate from the delivery mechanism.

```ts title="notification.ts"
type Notification = {
  event: "order.confirmed";
  recipientId: string;
  variables: { orderNumber: string };
};

const notification: Notification = {
  event: "order.confirmed",
  recipientId: "customer_123",
  variables: { orderNumber: "ORD-123" },
};
```

This example describes application data. It does not prescribe a messaging provider’s API format.

## Keep templates easy to review

Give each template a clear purpose. Review the text with real examples and make missing variables explicit.

### Prefer small building blocks

Separate the event, the template, and the delivery adapter. A change to the wording should not require changing the business event.

1. Receive an application event.
2. Select the appropriate template.
3. Resolve and validate its variables.
4. Queue delivery and track the result.

## Document the decisions

Write down which events produce messages, which recipients are eligible, and what happens if sending fails.

> A workflow is easier to maintain when its assumptions are visible.

Begin with one event and a small set of tests. Expand once the first workflow is easy to operate.
