قد يكون إرسال إشعار واحد بسيطًا. يبدأ التحدي عندما تحتاج عدة أجزاء من التطبيق إلى إرسال رسائل متشابهة.

## حدّد الحدث أولًا

ابدأ بالحدث المهم للمستخدم، مثل تأكيد طلب أو تحديث حساب. افصل معنى الحدث عن طريقة تسليم الرسالة.

```ts title="notification.ts"
type Notification = {
  event: "order.confirmed";
  recipientId: string;
  variables: { orderNumber: string };
};

const notification: Notification = {
  event: "order.confirmed",
  recipientId: "customer_123",
  variables: { orderNumber: "ORD-123" },
};
```

يصف هذا المثال بيانات التطبيق، ولا يحدّد شكل طلبات API لدى مزوّد المراسلة.

## اجعل القوالب سهلة المراجعة

امنح كل قالب هدفًا واضحًا. راجع النص باستخدام أمثلة واقعية، واجعل المتغيرات الناقصة ظاهرة.

### استخدم وحدات صغيرة

افصل الحدث عن القالب وعن موصّل الإرسال. ينبغي ألا يتطلب تعديل نص الرسالة تغيير الحدث التجاري.

1. استقبل حدثًا من التطبيق.
2. اختر القالب المناسب.
3. جهّز المتغيرات وتحقق منها.
4. أضف مهمة الإرسال إلى قائمة الانتظار وتتبع نتيجتها.

## وثّق القرارات

اكتب الأحداث التي تنتج رسائل، ومن يستحق تلقيها، وما الذي يحدث عند فشل الإرسال.

> تصبح صيانة سير العمل أسهل عندما تكون افتراضاته واضحة.

ابدأ بحدث واحد ومجموعة صغيرة من الاختبارات، ثم توسّع بعد أن يصبح تشغيله واضحًا.
